## 1. あだ名：名簿で付けたあだ名は、今、報告書の呼び名に使われているか

**使われている（これから生成される報告書だけ）。**

- 報告書の生成は、人の名前を `getDisplayName(adv)` で引く（app.js で115か所。交戦の記録・掛け合い・在席・成長の行も同じ）。
  `getDisplayName` は **あだ名（`nickname`）→ 呼び名（`callName`・EX-164）→ 本名** の順に引く。
- 実験：ミナのあだ名を「ミーちゃん」にして同じ種で生成し直すと、本文の「ミナ」がすべて「ミーちゃん」になった（「ミナ」は0回）。
- ★ 過去の報告書は変わらない（本文は生成したときの文字列で保存される）。
- ⚠️ 例外：データの文に名前を直書きしているものはあだ名に追従しない。
  - `idleLine`：鉄鍋「鉄鍋は袋の中身を…」、ロウ「ロウは古地図を…」、エルシー「エルシーは…」。エルネは EX-164 で「エルネは…」にした。
  - 過去の文（`data-past.js`）と特殊裁定のフックの文も同じ形かは未確認（あだ名を変えたときに残る旧名の洗い出しは、あだ名への反応を作るときに一緒にやるとよい）。
- 「あだ名への反応」を作るときに要るもの：**付けた（変えた）時点の印**が今は無い（`saveAdventurerMemo` は `attachmentScore` を足すだけ）。
  「付けた・変えたあとの最初の報告書で1回だけ」には、名簿の保存で `nicknameChangedAt`（または「まだ反応していない」旗）を冒険者に持たせ、帰還の処理で1行足して旗を下ろす形が素直（下の「掛け合い」と同じく、**帰還のとき**に足せば対比較の基準は動かない）。

## 2. いまの様子：エルシーの idleLine の仕組みと、全員に広げるときの器

- 名簿の詳細の欄は、**犬だけ「いまの様子」**、人間は「冒険譚」（`adventurerTaleHtml`）。
  - 犬：`obsession.idleLine`（「エルシーは誰かの足元に鼻先を寄せて、出発を待っていた。」）を1行。無ければ定型「いまは誰かの足元で、出発を待っている。」
  - 人間：`obsession.positiveLine` を1行。
- ★ **人間の `idleLine` は報告書の本文に使われている**（執着の行。`app.js` の夜・静かな道・待ち時間の分岐で `obs.idleLine`）。
  → これを名簿の「いまの様子」に流用すると、文を直したときに**報告書の基準まで動く**。器は別に作るのがよい。
- 器の案（データ）：

```js
// data-now.js（新規。index.html の FILES に足す。構文チェックは data-*.js を自動で拾う）
window.masterNowLines = {
  adv_mina: [
    { when: "waiting",  text: "（待機中のとき）" },
    { when: "injured",  text: "（負傷して休んでいるとき）" },
    { when: "returned", text: "（帰ってきてすぐ）" },
    { when: "away",     text: "（遠征に出ているあいだ。名簿では「留守」の札の下に）" }
  ],
  adv_elsie: [ /* 今の idleLine をここへ移すかは別判断（移すなら名簿の表示だけが動く） */ ]

```

- 選び方の案：その人の状態（待機中／負傷／遠征中／帰還直後）で `when` を絞り、複数あれば**日替わり**（暦の日数で順に替える。乱数は使わない＝リロードで変わらない）。
- 出す場所の案：名簿の詳細の欄（今のエルシーと同じ）。ホームの窓でその人をタップしたときの一言（EX-161 の `ROOM_REACTIONS`）に寄せる案もある。
- 文面は作者が書く（チャット側は下書きを出せる）。

## 3. 二人の掛け合い：一緒に遠征した回数を、今どこかで数えているか

**数えていない（保存した値は無い）。ただし `state.reports[].adventurerIds` から数えられる。**

- 前例：冒険者の過去（EX-146）は「その冒険者と遠征した回数」を `state.reports` から数えている（`pastExpeditionCount`。定型報告書＝掃除は除く）。二人なら「両方の id を含む報告書の数」で同じ形にできる。
- 今ある掛け合い：`generatePartyBanterLog`（人間2人をランダムに選び、65% で依頼の分類ごとの文を1行）。**帰還のとき**に足している（`appendPartyBanterToReport`）ので、対比較の基準の外。
- 守る制約：
  - 報告書の乱数は**出発時の種だけ**から作る（EX-138）。
  - **報告書の生成の中で履歴を読まない**（EX-148 Q4・PR #150 で、履歴を読む例外をやめた）。
  - → 二人の掛け合いは、今の掛け合い・過去の合図と同じく**帰還の処理で足す**のが素直（そこでは `state.reports` を読んでよい。過去の合図が前例）。
- 器の案：

```js
// data-pairs.js（新規）
window.masterPairBanter = [
  { pair: ["adv_mina", "adv_gadd"], thresholds: [3, 6, 10], lines: [["（3回目）"], ["（6回目）"], ["（10回目）"]] },
  // 3組ほど（全10組は却下済み＝物量が大きすぎる）
];
```

- 出し方の案：その二人が同じ編成で、一緒の回数がしきい値を越えた回の報告書に1行（過去の合図と同じ「越えた回だけ」）。今の汎用の掛け合いと同じ回に重なったら、こちらを優先して汎用は出さない。
- 未確定（正本の節のまま）：3組をどれにするか・何回で出すか・文面。

## 4. 相談→固有依頼→感謝の連鎖：作者が文面を書き込める表の形

★ 一人ぶんの項目を並べた雛形。順番は 鉄鍋 → ミナ → エルネ → ロウ → エルシー → 受付嬢（正本の節）。
置き場の案：新しい `data-bonds.js`（`index.html` の `FILES` に足す。構文チェックは自動で拾う）。

```js
// data-bonds.js（案）。★ 文面はすべて作者が書く。配列の1要素＝会話の窓の1段落（台本の空行）。
window.masterBondChain = {
  // 連鎖を始める条件：6件のうち何件を（未達でなく）終えたら最初の人の相談が始まるか（正本「さらに2つほど」）
  startAfterSixCleared: 2,
  chain: [
    {
      id: "bond_gadd",
      adventurerId: "adv_gadd",          // 相談してくる人
      // ── 相談（会話）──
      consult: {
        where: "home",                   // ホームに会話の窓で（受付嬢の会話と同じ器）
        speaker: "鉄鍋",                  // 話し手の表示（呼び名・5文字以内）
        paragraphs: [
          ["（相談の1段落目）"],
          ["（相談の2段落目）"]
        ]
      },
      // ── 固有依頼 ──（★ 掲示板に一度に1件だけ。相談を読んだら掲示板に出る）
      quest: {
        id: "quest_bond_gadd",
        title: "（依頼名）",
        category: "生活",                // 生活／採取／保全／護衛／討伐／調査／捜索 など今の分類
        area: "（場所）",
        durationBand: "near_10m",        // 所要時間の帯（data-quests.js の帯の名前）
        danger: 1,
        summary: "（掲示板の概要）",
        requires: ["adv_gadd"],          // 編成に必ず入れる人（本人が行く依頼なら本人）
        allowedItems: [],                // 持たせてよい支給品（★ 既定は全禁止。書かないと支給品の行が出ない）
        report: "fixed",                 // fixed＝定型の報告書（掃除と同じ形）／generated＝工程エンジン
        reportLines: ["（定型なら本文の行）"],
        observationTarget: "なし"
      },
      // ── 感謝（会話）──
      thanks: {
        when: "reportStamped",           // reportOpened（開いたら）／reportStamped（読了の封のあと）
        speaker: "鉄鍋",
        paragraphs: [["（感謝の1段落目）"]]
      },
      // 次の人へ進む条件
      next: { id: "bond_mina", when: "thanksRead" }  // thanksRead（感謝を読んだら）／afterCleared:N（さらにN件終えたら）
    },
    { id: "bond_mina",     adventurerId: "adv_mina",  /* 同じ形 */ next: { id: "bond_elne", when: "thanksRead" } },
    { id: "bond_elne",     adventurerId: "adv_elne",  /* 同じ形。材料：薬草 */ next: { id: "bond_row", when: "thanksRead" } },
    { id: "bond_row",      adventurerId: "adv_row",   /* 同じ形 */ next: { id: "bond_elsie", when: "thanksRead" } },
    { id: "bond_elsie",    adventurerId: "adv_elsie", /* ★ 下の注意 */ next: { id: "bond_reception", when: "thanksRead" } },
    { id: "bond_reception", adventurerId: null,       /* ★ 下の注意 */ next: null }
  ]

```

### 実装に入る前に決めること（構造のコスト）

- **固有依頼は1件ずつ新しい依頼になる。** 1件ごとに、`masterQuests` への登録・`canUseItemInQuest` の許可リスト（★ 既定は全禁止）・`generateReport` の分岐（定型なら掃除と同じ形が軽い）・エルシーの行の方針（インライン／`withElsieLog` のどちらか）が要る（CLAUDE.md「新しい依頼ジャンルを追加するときの最小差分ポイント」）。
  → 雛形の `report: "fixed"` を既定にすると、文面だけで足せる（工程エンジンを通すと対比較の基準と調整が増える）。
- **「一度に1件だけ」と掲示板の6枠**：固有依頼を枠の内にするか外（緊急依頼と同じ枠外）にするか。`oneTime`（一度きり）にするか。
- **エルシーの相談・感謝**：犬なので人間の発話・行動（説明する・記録する・声をかける）をさせない（`check-elsie-actions.js` は報告書の生成だけを洗うので、会話の文は目で見る必要がある）。相談は「受付嬢が代弁する」形などが要る。
- **受付嬢の固有依頼**：受付嬢は出発させられない（冒険者ではない）。誰が行くのか（全員で行く／プレイヤーが選ぶ）を決める。「記録をつける側の人が最後に記録される」（正本）の形にするなら、報告書の書き手欄の扱いも要る。
- **体験版の終わりの合図**との関係（正本の未確定）：受付嬢の感謝のあとにするか、今の条件（護衛を開いた∧名前の封）のままか。
- 「さらに2つほど」は数（`startAfterSixCleared`）として表に置いた。未達を数えるかは①②の会話と同じ規則（未達は数えない）を既定にする案。
