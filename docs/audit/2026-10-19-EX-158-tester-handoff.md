## 【2】テスター用に版を固定する方法（案・停止）
いまの配信：GitHub Pages が main のルートをそのまま配る（main へのマージで中身が変わる）。同じ場所（kaz6.github.io）なので localStorage は作者の版と共有される（保存の鍵は `expeditionGuildLogMockV011` と `…_bound`）。

| | 内容 | 良い点 | 悪い点 |
|---|---|---|---|
| **A（推奨）** | `trial/` に凍らせた写しを置く（`kaz6.github.io/guild-log-mock/trial/`）。写しは `scripts/make-trial.js`（外部依存ゼロ）で作る。**保存の鍵はパスから決める**（`/trial/` を含むなら鍵に `_trial` を足す。写しはバイト単位で本体と同じ） | 追加の仕組みが少ない。凍結＝その写しを作り直さない限り変わらない。作者が両方開いても保存が混ざらない | 約10,000行の写しが repo に増える（pr-review の差分が大きくなる→写しの更新は単独 PR）。公開 repo に写しも載る |
| B | 別の公開 repo（例 guild-log-trial）へ写しを置く。オリジンが別になるので鍵は分けなくてよい | 本体の repo が汚れない。保存は自然に分かれる | repo が増える。手で運ぶ工程が増える（運び忘れ） |
| C | Pages の公開元を Actions に替え、main は `/`、タグ（例 `trial-1`）の中身を `/trial/` に配る | 写しが repo に残らない | 配信の仕組みを替える（今は動的ビルド）。壊すと本体の配信も止まる |

- 推奨は A：**凍結を「写しを作る」という明示の操作にする**（うっかり変わらない）。更新するときだけ `node scripts/make-trial.js` → 単独 PR。
- どの案でも：保存の互換（`schemaVersion`）は写しの中で閉じる。テスターの保存を作者の版が読むことはない。
- 判断してほしいこと：A／B／C のどれか。A なら写しを更新する条件（例：不具合の修正だけ入れる）。

## 【3】体験版の終わり（点検結果と案・停止）
- 範囲：EX-049 と DECISION_LOG（2026-09-15 EX-101／2026-09-18 EX-127）。**9ジャンル一通り・喪失（行方不明・死亡）は起こさない・「隊商護衛のクリアが山場」・「締めとして『最初のひとつに名前を付けた』で終わるのが望ましい」**。
- **終わりに当たる出来事は2つ**：① 隊商護衛をクリアして買い出しが解禁される（山場）／② 生態目録で**最初のひとつに名前の封をする**（締め）。
- **いま画面に終わりの合図は出ない**。コードに終わりの判定も画面も無い（`grep` で0件）。依頼は消化数1〜3で戻ってくるので、遊び続けられるし、**どこで終わりか分からない**。
- ⚠️ 順序は固定でない：**命名は O の軸を7種類書けば解禁**で、報告書で観察対象（森喰い兎）に会って読了の封をすれば枠が出る。**護衛の前にも命名できる**（観察記録票は護衛のあとに解禁だが、O はプレイヤーが書くので無くても書ける）。
- 案：
  - **A（推奨）**：「護衛を受けた報告書が1通以上 ∧ 名前の封が1つ以上」のとき、受付嬢が**1度だけ**一言（例：「最初の名前が、記録に残りましたね。……ここまでが、いまお見せできる分です。」）。ホームのカード1枚、読んだら消える。遊び続けるのは縛らない。
  - B：A に加えて、ホームに**恒久の一枚**（「体験版はここまで／続けても構いません」＋感想の宛先）を出す。終わりは明確だが、遊びの途中感が消える。
  - C：何も出さない（現状）。テスターが終わりに気づけない。
- 判断してほしいこと：A／B／C。「護衛クリア」の定義（報告書があれば足りるか、結末が成功系のときだけか）。感想の宛先を画面に出すか。

## 【4】最初から最後まで、手を貸さずに通るか（点検結果）
方法：`?dev` なしの本番の経路を Playwright で通した（Playwright の時計 `page.clock` で実時間を縮めた。UI は本番どおりにクリック）。

- **通った**：面接→酒場（10秒）→掃除（20秒）→廃屋→道標→畑→納屋→隊商護衛（3時間）→買い出し→…と、**掲示板に出た依頼を一巡**（捜索チェーン2件と救済は出る条件を満たさないので通していない）。仮想36時間・報告書46通まで進めて、**console error 0・詰まり0**（途中で「遠征開始が押せない」と出たのは点検用スクリプトの時間の読み違いで、時計を正しく進めると解消）。
- **借金→運営不能→戻る**：本番の経路で**つながっている**。借入（受付嬢の言葉）→再び赤字で運営不能→ホームのカードの「最後に綴じた記録まで戻る」→確認→「戻る」で、運営不能が解け、報告書数と所持金が綴じた時点へ戻る（通知「…に綴じた記録まで戻った。」）。綴じる欄は**最初の報告書を開いてから**出る（開く前は0、開いたあとは1）。綴じていないときは「戻れる場所は、最初しかない」＋「最初からやり直す」→確認（文言から Mock を外した）→面接へ。
- **遠征中にリロード**：遠征は残り、時間が過ぎてから開くと帰還カードが出る（オフライン進行）。
- **詰まる・壊れる・説明なしでは分からない箇所**：
  1. **終わりの合図が無い**（【3】）。
  2. **運営不能は自然には踏みにくい**：通しで所持金は 300→270→…→676 と増え続けた（報酬が遠征費を上回る）。借金も運営不能もテスターはまず見ない。つながってはいるが、**本番の動線で出会う機会がほぼ無い**（設計どおりなら問題ではない。見せたいなら別の話）。
  3. **待ち時間が長い**：隊商護衛は3時間、巡回・捜索は2時間。**「扉の音を待たず」は Mock 専用で、テスターには無い**。遠征中の画面に「いつ帰る」の目安（所要時間）が出ているかは確認した（掲示板の所要時間欄）が、閉じて戻ってくる前提の説明は無い。
  4. **綴じる欄の促しは「最初の報告書を開いたあと」から**で、読んだ人にしか出ない（意図どおり）。
  5. 起動直後の案内は受付嬢の一言のみ（「依頼掲示板を確認できます」）。**操作の説明は無い**（説明しない前提どおり）。
