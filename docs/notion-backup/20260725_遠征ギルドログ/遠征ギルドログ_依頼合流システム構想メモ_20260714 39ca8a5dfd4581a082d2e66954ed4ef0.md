# アイデアの概要

同じ地域に別の依頼（依頼A＝調査、依頼B＝討伐）が存在し、**同じタイミングで出撃させると合流フラグが立ち**、互いの任務を少し手助けする。プレイヤーが依頼の組み合わせと出撃タイミングを読む余地が生まれる。

# 作者が感じている懸念

- 合流すると最低8人になる。人数が多すぎないか。
- 特に戦闘依頼は「ボコボコにできてしまう」。
- これをやるなら「何人でも連れていける」ことになりかねない。

# 悩みの正体（チャットでの言語化）

**合流を「戦力の足し算」にした瞬間に、人数制限が意味を失って壊れる。**

逆に言えば、合流を戦力以外のものとして定義すれば 8人問題は消える。

# 有力な方向性（未決定・叩き台）

## 案：「情報と余波の共有」型（戦闘には参加しない）

- 合流しても**互いの戦闘には参加しない**。戦力は合算されないので既存の人数制限・戦闘バランスが壊れない。
- 代わりに互いの行動が**相手の報告書に影として映る**。
    - 例：「隣の谷で騒ぎがあったせいか、調査対象は巳を捨てて移動していた」（調査A側のログ）
    - 例：「調査隊が残した目印のおかげで、巣の位置を早く特定できた」（討伐B側のログ）
- **記録係が2つの報告書を読み比べて初めて全体像が見える** → 本作の売り（記録を読む楽しさ）と直結する。
- 合流を戦闘の解決策にすると凡庸なパーティ拡張になるが、読み物として交差させれば唯一無二になる。
