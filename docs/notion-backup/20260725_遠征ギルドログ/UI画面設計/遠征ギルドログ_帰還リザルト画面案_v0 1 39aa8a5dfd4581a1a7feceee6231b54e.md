位置づけ: 遠征終了時に表示する「帰還リザルト画面」の仕様メモ。通常の遠征ログ本文とは別に、ギルド報告書風の文体で、今回の遠征結果を短くまとめる画面として扱う。

## 1. 結論

帰還リザルト画面は採用候補としてかなり有力。

ログ本文は「硬質な探索記録 + 生活感少し」のD案を基本にする。一方で、帰還直後のリザルト画面だけは「ギルド報告書風」に寄せる。

理由：

- 遠征ログは読む体験
- リザルト画面は整理して受け取る体験
- 3行要約 + 評価 + 報酬 + 負傷/履歴更新があると、1回の遠征に区切りが生まれる
- 報告書風にすることで、プレイヤーがギルドマスター/記録係である感覚が強くなる

## 2. 画面の役割

帰還リザルト画面は、以下をまとめて見せる：遠征名、結果ランク、3行要約、報酬、取得アイテム、負傷/行方不明/死亡、履歴に残る出来事、受付の女の子の一言、詳細ログを見るボタン、冒険者詳細へ移動する導線

## 3. MVPでの最小構成

**必須**：遠征名、結果（大成功/成功/部分成功/失敗）、報告書3行、報酬、負傷/状態変化、詳細ログボタン

**できれば**：評価ランク、受付コメント、履歴に保存されたログ

**後回し**：名声度、冒険者ごとの評価ポイント、S〜Fの細かい評価、報告書スタンプ演出、受付の表情差分、紙の報告書UI演出

## 4. 評価ランク案

### 4.1 MVP案

既存の判定式に合わせて4段階でよい。

| 判定結果 | 表示名 | 用途 |
| --- | --- | --- |
| 大成功 | 優良報告 | 報酬増、注目ログ、称号候補 |
| 成功 | 達成 | 標準報酬 |
| 部分成功 | 条件付き達成 | 報酬減、負傷/遅延/不足あり |
| 失敗 | 未達 | 報酬なし/低下、救助や再挑戦へ派生 |

この表記は、S/A/B/Cよりも世界観に合う。ただし、ゲームとして分かりやすくするなら、内部的にランク文字を持ってもよい。

### 4.2 将来案

| 評価 | 意味 | 備考 |
| --- | --- | --- |
| S | 想定を大きく上回る成果 | レア報酬/名声上昇/称号候補 |
| A | 十分な成功 | 通常より良い報酬 |
| B | 標準成功 | 通常報酬 |
| C | 条件付き成功 | 報酬減/負傷/遅延 |
| D | 失敗 | 再挑戦/救助派生 |
| E | 重大失敗 | 行方不明/重傷 |
| F | 壊滅的結果 | 死亡/遺品/墓地派生 |

ただし、MVPでいきなりS〜Fを入れるとゲームが評価ゲーに寄りすぎる可能性がある。最初は「大成功/成功/部分成功/失敗」で十分。

## 5. 文体方針

### 5.1 遠征中ログ

D案。硬質な探索記録をベースに、必要な場面だけ生活感を入れる。

例：

霧で道が消えた。

ミナは地図の端を押さえ、苔むした石を探した。

帰還は遅れたが、誰も森には残されなかった。

### 5.2 帰還リザルト

ギルド報告書風。短く、事務的に、今回の成果をまとめる。

例：

任務: 霧の森の薬草採集

結果: 条件付き達成

報告: 指定薬草を一部納品。帰還時刻に遅延あり。行方不明者なし。

## 6. リザルト画面サンプル

### 6.1 小鬼の洞窟の見回り / 大成功

遠征名: 小鬼の洞窟の見回り／結果: 優良報告／評価: A

報告書：

- 小鬼の群れを洞窟奥へ追い払った。
- 支給品の小盾が被弾を防ぎ、負傷者は出なかった。
- 周辺の安全を確認。衛兵隊へ報告済み。

報酬：金貨30、小鬼の牙1／状態変化：なし

受付コメント：「おつかれさまでした。小盾、持たせておいて正解でしたね。」

### 6.2 霧の森の薬草採集 / 部分成功

遠征名: 霧の森の薬草採集／結果: 条件付き達成／評価: C

報告書：

- 指定薬草の一部を採集した。
- 濃霧により帰還時刻に遅延あり。
- 古い地図の使用により、行方不明は回避された。

報酬：金貨25、薬草2／状態変化：エルン 軽い疲労

受付コメント：「全員戻ってきています。それが一番です。」

### 6.3 古い薬草園の毒草調査 / 成功

遠征名: 古い薬草園の毒草調査／結果: 達成／評価: B

報告書：

- 指定された毒草を確認し、標本を回収した。
- 解毒薬を使用。重症者なし。
- エルンの判別により、類似毒草の誤採取を回避。

報酬：金貨50、毒草標本1／状態変化：なし

受付コメント：「エルンさんがいてくれて助かりました。薬草園は、見た目だけでは分かりませんから。」

### 6.4 迷子の新人を探せ / 成功

遠征名: 迷子の新人を探せ／結果: 達成／評価: B

報告書：

- 霧の森内で対象者を発見した。
- 包帯による応急処置を実施。
- 対象者を保護し、ギルドへ帰還。

報酬：金貨40、ギルド信頼+1／状態変化：汎用新人（救助された履歴を追加）、ミナ（救助回数+1）、エルン（治療履歴+1）

受付コメント：「……よかった。ちゃんと、帰ってきましたね。」

### 6.5 遺品回収 / 失敗後派生

遠征名: 遺品回収／結果: 回収完了／評価: 記録対象

報告書：

- 対象者本人は発見できず。
- 泥の中から、名の刻まれた小盾を回収。
- 遺品を記録棚へ移管し、死亡者名簿を更新。

報酬：なし／状態変化：対象者（死亡扱い）、遺品（小盾を記録棚へ登録）

受付コメント：「記録棚に、場所を作っておきます。」

## 7. データ構造案

**ExpeditionResult**：result_id, mission_id, party_member_ids, item_ids, result_type(great_success/success/partial_success/failure), result_grade(S/A/B/C/D/E/F/none), result_label(優良報告/達成/条件付き達成/未達/記録対象), summary_line_1〜3, reward_gold, reward_items, injury_summary, history_updates, receptionist_comment_id, detail_log_ids, created_at

**ResultSummaryTemplate**：template_id, mission_type, result_type, condition_tag, summary_line_1〜3, weight

**ResultGradeRule**：grade_id, result_type, min_score, max_score, reward_multiplier, fame_delta, injury_multiplier, missing_multiplier, notes

## 8. 実装方針

MVPでは、判定式の結果をそのままリザルト画面に流す。

流れ：遠征実行 → mission_score計算 → result_type決定 → 負傷/行方不明/死亡判定 → 報酬決定 → summary_line_1〜3を生成 → 受付コメントを選択 → 帰還リザルト画面を表示 → 必要な履歴ログを冒険者に保存

## 9. 採用判断

**MVPで入れる**：帰還リザルト画面、3行報告書、結果ラベル、報酬、状態変化、詳細ログへの導線

**MVPでは軽く入れる**：評価ランク、受付コメント、履歴更新表示

**v0.2以降**：S〜Fの細かい評価、名声度、冒険者個人への評価影響、報告書スタンプ演出、紙UI演出、受付表情差分

## 10. 注意点

- 評価ランクを強く出しすぎると、プレイヤーがログよりスコアを追うゲームになる
- MVPでは「評価」より「今回の遠征で何が起きたか」を主役にする
- S〜Fは気持ちいいが、最初は大成功/成功/部分成功/失敗で十分
- 報告書風に寄せすぎると無機質になるため、受付コメントで温度を戻す
- 死亡や遺品は、評価ランクではなく「記録対象」として別扱いにしてもよい

## 11. 現時点の推奨

最初のモックアップでは、帰還リザルト画面を入れる。ただし、S〜Fの細かい評価は後回しにする。

MVPモックアップでの表示：結果（大成功/成功/部分成功/失敗）、報告書3行、報酬、状態変化、詳細ログを見る、冒険者詳細へ

これで十分に「1回の遠征が締まる」画面になる。
