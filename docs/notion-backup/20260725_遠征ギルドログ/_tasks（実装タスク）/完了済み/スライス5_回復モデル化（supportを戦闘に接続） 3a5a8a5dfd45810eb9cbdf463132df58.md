# このタスクの意義

**support stat を初めて戦闘計算に接続する。** これまで戦闘は job別HPと前衛配分だけで動いていたが、初めて stat が戦闘に意味を持つ。

# やること（スコープ）

`simulateBattle` に回復処理を追加し、回復イベントを `events` に含めてドラマログに描画する。対象は**隊商護衛のみ**。

## 回復ロジック

- **回復役：support が最も高い人間の冒険者**（エルネ固定ではなく support 値で決める）。
- **発動条件（B案）**：味方の誰かが「手負い」または「深手」になったときに発動。毎ラウンド自動ではない。
- **包帯がないと回復は起きない。** 回復は包帯を1個消費する。尽きたら回復できない。
- 回復対象は、最も重い状態（深手＞手負い）の味方を優先。
- 回復量は固定値でよい（叩き台を提示して確認を取る）。
- 回復により状態が戻る場合（深手→手負いなど）は、その遷移もドラマログに出す。

## 包帯の保持元とエルシー

- 包帯は支給品。**エルシーが持つ包帯も、supportが高い人間が優先的に使う。**
    - エルシーは道具を使えない（人間行動禁止）ので、**包帯の「運び手」**として扱う。使うのは人間。
    - 既存の支給品ロジック（アイテム保持）を確認し、エルシーの分も含めて包帯の総数を集計する。

## ドラマログの回復行（例）

- 「エルネはガッドに駆け寄り、傷に包帯を巻いた（ガッドは10回復）（包帯消費：1）」
- 回復量の表記はスライス4のダメージ表記と揃える（マイナスなし・「N回復」形式）。

# 制約

- **エルシーは回復行の「施術者」にはならない。** 包帯を運ぶだけ。回復を施すのは support の高い人間。
    - エルシーは従来どおりダメージ行・状態行に登場させない。
- 回復は包帯があるときだけ。なければ発動しない。
- 時系列順・トドメが最後、は維持（スライス3.5）。回復行もラウンドの正しい位置に入ること。
- 1依頼1関数構造を維持
- 最小差分を優先

# 確認事項（Claude Code が記入 → チャットClaude が回答）

## Claude Code からの質問（2026-07-22・実装前の確認）

### 理解していること（相違があれば指摘を）

1. 回復役＝**発動時点で生存している人間のうち support 最大**（現パーティだとエルネ support2 が自然に選ばれる。同点は編成順。回復役自身が倒れていたら次点者に交代）。fighters に `support: a.stats?.support ?? 1` を追加（既存の courage/combat 参照と同じ形式。support の既存参照は成長カテゴリと名簿表示のみで、矛盾なし）。
2. 発動（B案）＝そのラウンドの被弾処理で誰かが**手負い/深手に遷移したとき**、ラウンド末に1回発動。毎ラウンド自動ではない。戦闘不能は発動条件外・回復対象外（手当てでは戻らない）。
3. 対象＝生存者のうち最も重い状態（深手＞手負い）。回復役自身が最重度なら自己手当て（専用文）。
4. 包帯＝`getAllItemIds` の平坦化リストで `item_bandage` を数える（**エルシーの所持分も自動的に含まれる**＝運び手仕様を満たす）。なければ発動しない、使えば1個消費。モックに恒久在庫は無いので消費は戦闘内の概念（報告書に残るのみ）。
5. 時系列＝回復は**戦闘が続く場合のみ**ラウンド末に発動（勝利/決着ラウンドでは発動しない）。これでトドメ後に回復行が出ることは構造的にない。events に `{type:"heal", round, healer, target, amount}` をラウンド位置に記録。状態の戻りは status イベント（from深手→to手負い等）として記録し、回復専用の文面で描画。
6. 副作用（仕様どおりの振る舞いとして容認）＝回復で allyRatio が上がるため、以降の撤退判断・最終 stage に自然に影響する（support 接続の意義そのもの）。先回り調整はせず、分布比較で報告。
7. 包帯の撤退スコア効果（hasEffectiveItem）は戦闘開始時の静的判定のまま（消費しても心理効果は残る解釈・最小差分）。動的にしたければ指示を。

### 質問1：数値の叩き台

- **回復量：固定15**（推奨）。根拠：前衛の被弾は毎ラウンド約13〜18なので「約1ラウンド分を取り戻す」感触。ガッド(120)の手負い閾値84に対して過剰でない。代案：`10+support×3`（エルネ=16。将来のランダム冒険者でスケールするが、仕様の「固定値でよい」に従い今回は固定推奨）。
- **発動上限：1ラウンド1回まで**＋総回数＝包帯数。人工的な別上限は設けない。

### 質問2：ドラマログの文面叩き台（回復は新規要素なので最小の新規テンプレが必要）

- 回復行：「エルネ・シェルカはガッドに駆け寄り、傷に包帯を巻いた（ガッドは15回復）（包帯消費：1）」／自己手当て：「エルネ・シェルカは自分の傷に手早く包帯を巻いた（…）」
- 状態の戻り（回復版の遷移文）：深手→手負い「○○の顔に血の気が戻った。まだ戦える。」／手負い→健在「○○の動きが軽くなった。傷は浅い。」

### 質問3：回復行・状態の戻り行の色

- 推奨：**既存パレットの緑 `--success #92ba7d`**（実効コントラスト約7.7:1で視認性OK。ダメージ赤・手負い橙との対比で「持ち直した」が一目で分かる）。代案：色なし（actionと同じ）。

→ 問題なければ「OK」だけで。修正があれば個別に指定ください。

## 回答（チャットClaude が記入・2026-07-22）

全項目OK。理解7点すべて承認。

- **質問1（回復量）**：固定15で確定。根拠（約1ラウンド分・手負い閾値84に対して過剰でない）も妥当。
- **質問2（文面）**：OK。1点だけ任意修正 —— 手負い→健在の戻り文「傷は浅い。」を「もう案じることはない。」に変えると、手当てした側への安心感が出て support キャラの株が上がる。しっくりこなければ元のままでよい。
- **質問3（色）**：緑 `#92ba7d` で確定。

### 理解6について（最重要）

理解6（回復で allyRatio が上がり撤退・stage に影響する）は**まさに狙いどおりで容認**。ただしこれが support 接続の本体なので、**シミュレーション比較（回復なし・あり）が今回最重要**。「エルネ＋包帯で無双にならないか」を必ず確認し、結果を実装結果に載せること。理想は「生還率は上がるが、無双はしない」。

### 補足：将来、各パラメータは変動する想定（レベルアップ概念）

- 現在 stat は遠征帰還時に対象statを+1（上限5）で成長する。将来はこれをレベルアップ概念として拡張する想定。
- **つまり support も変動する。** 今回の回復ロジックが `a.stats?.support ?? 1` を都度参照する stat 駆動である限り、support が上がれば回復役の選定や（将来 `10+support×3` を採用すれば）回復量も自然に追従する。
- 今回は回復量を固定15にするが、**将来 support 変動が本格化したら、回復量を support 依存にするか再検討する**余地がある（今回はやらない）。

実装に進んでOK。
