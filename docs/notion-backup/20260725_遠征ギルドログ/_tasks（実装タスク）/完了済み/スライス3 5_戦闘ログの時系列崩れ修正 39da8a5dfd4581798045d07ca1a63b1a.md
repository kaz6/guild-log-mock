# 現象

実機確認（2026-07-14、翻訳問題解決後）で、**戦闘が終わったはずなのに、そのあとも戦闘ログが続いている**。

## 実際の出力（スクショより・時系列順）

1. 「ロウが盾ごと体当たりし、野盗を押し崩した！（野盗に-15！）」
2. 「**鉄鍋の一撃で野盗は総崩れになり、街道から姿を消した（野盗に-19！）**」 ← **トドメの締め文**
3. 「エルネ・シェルカはかすめる一撃を払い、浅く傷を負った（エルネ・シェルカに-3）」 ← **トドメ後なのに被弾**
4. 「ロウは前で受け止めたが、衝撃は殺しきれなかった（ロウに-1）」 ← **同上**
5. 「鉄鍋はよろけた拍子に、野盗の一撃をまともに受けた！（鉄鍋に-14！）」 ← **同上**
6. 「幾人かは傷を負ったが、隊商は止まらずに外縁の先へ抜けた。」 ← 結果

**野盗が「街道から姿を消した」あとに、野盗から攻撃を受けている。**

# なぜ問題か

- **ドラマの順序が崩壊している。** トドメのあとに被弾するのは物語として致命的。
- 案Dの価値は「戦闘を読み物として体験させる」こと。時系列が壊れていると、数値もドラマも意味を失う。

# 仮説（調査の取っかかり。断定ではない）

以下のどちらか、もしくは別の原因。**まず調査して確定させること。**

## 仮説A：イベントの並び順が種別順になっている

- `events` をラウンド順ではなく、**種別順（dealを全部 → takeを全部）**で描画している。
- だとすれば「与ダメ→トドメ」が先に全部出て、そのあとに被ダメがまとめて出る。**スクショの症状と一致する。**

## 仮説B：敵が倒れたあとも反撃イベントが生成されている

- `simulateBattle` が、敵HPが0になったラウンドでも敵の反撃処理を実行している。

- 敵が倒れたあとの反撃イベントが生成されている場合は、それも止める。

# 実装結果（Claude Code 記入・2026-07-14）

## 原因（確定・生成側と描画側の合わせ技）

- **生成側**：`simulateBattle` はラウンド内を同時解決（味方全員の与ダメ一括→敵の反撃一括）で記録し、勝敗チェック `enemyHp <= 0` が反撃処理の後にある。よって敵HPが0を割ったラウンドでも反撃イベントが記録される（仮説Bはエンジンレベルで真）。
- **描画側**：トドメ行（決着宣言の文章）を「全イベント中最後の deal」の位置にそのまま出していたため、同ラウンドの被弾・状態行がその後に続いた。スクショの症状と完全一致をnodeで再現済み（最終ラウンド deal×4→take×3、トドメ後に戦闘行3件）。
- 仮説A（全体の種別ソート）は不正確：並びはラウンド順で、ラウンド内だけ「与→被」の順。

## 変更したファイル

- `app.js`：`generateCaravanBattleDramaLog` の描画部のみ（+9/-1行）。トドメ行を退避して全戦闘行の末尾に付与。最終ラウンドの描画順は「与ダメ（トドメ以外）→被ダメ→状態変化→トドメ」。**events・エンジン・判定結果は不変**（裁定どおり案i）。
- `scripts/merge-remote.sh`（新規）：追加作業1。fetch→main切替+pull→マージ→push→リモート作業ブランチ削除。未コミット変更があれば中断（set -euo pipefail）。[git-sync.sh](http://git-sync.sh)（pull専用）と役割分離。
- `docs/DECISION_LOG.md` / `docs/SESSION_STATE.md`：裁定と残タスク（エンジンの死後反撃＝別タスク）を記録。

# 回答（チャットClaude・2026-07-14）

## 判断：**案i（ドラマ層の並べ替えのみ）で進めること。**

### 理由

- 今回のタスクは**読み物としての順序**を直すもの。**戦闘の判定を変えることではない。**
- エンジン側で反撃を止める（案ii）と「護衛成功（負傷）→ 護衛成功」に結果が変わる。これは**バランス変更**であって、時系列バグの修正ではない。混ぜてはいけない。
- 「打ち合いの応酬で鉄鍋が傷を負い、その中でロウの一撃が決着をつける」——**ドラマとしても案iの方が正しい因果**になる。トドメが最後に来るだけで、被弾は決着前に起きたことになる。

### 仕様の矛盾についての裁定

タスクに書いた「敵が倒れたあとの反撃イベントが生成されている場合は、それも止める」という指示を**撤回する**。

「戦闘の判定結果は変えない。順序だけを直す」の方が優先。矛盾する指示を出したのはこちらのミス。

### 追加指示

- **エンジン側の「死後の反撃」問題は、別タスクとして残すこと。** 今回は触らない。
- 修正は描画関数内のみ（最小差分）。events・判定結果は1ビットも変えない。
