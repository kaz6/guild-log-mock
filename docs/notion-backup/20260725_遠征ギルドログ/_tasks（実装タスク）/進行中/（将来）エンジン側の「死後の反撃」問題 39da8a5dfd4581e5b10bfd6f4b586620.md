# （将来）エンジン側の「死後の反撃」問題

> ステータス: **未着手・将来タスク**（すぐにはやらない）/ 作成: 2026-07-14
> 

> 発見経緯: スライス3.5（時系列崩れ修正）の調査中に Claude Code が発見。
> 

# 問題

`simulateBattle` はラウンド内を「味方全員の与ダメ一括 → 敵の反撃一括」の同時解決で記録している。

そして**勝敗チェック `if (enemyHp <= 0) break` が反撃処理の後にある**ため、

**敵HPが0を割ったラウンドでも、敵の反撃が実行・記録される**（＝「死後の反撃」）。

# なぜ今すぐ直さないのか

- これを直すと**最終ラウンドの被ダメが消える → 味方HP残量が増える → stage が中から軽に変わる**。
- 具体例：「護衛成功（負傷）」が「護衛成功」に変わるケースが出る。
- つまり**バランス変更を伴う**。時系列バグの修正とは別問題として切り離す。
- スライス3.5 では**描画側の並べ替えのみ**で対処した（トドメ行を最後尾に送る）。

# 検討すべきこと（着手時）

- そもそも「死後の反撃」はバグなのか、仕様なのか。
    - バグとする立場：倒した相手に殴られるのは不自然。
    - 仕様とする立場：同時解死的な「相訓ち」はむしろドラマとして自然。最後の一撃を放つ前にこちらも殴られている、と読める。
- 直す場合、**戦闘バランスの再調整が必要**（stage の分布が変わる）。
- プレイでの手触りを見てから判断するのが安全。

# 位置づけ

- 掴み体験の実装が一通り終わり、**実際にプレイしてバランスを見る段階で検討**する。
