# ⚠️ 方針を改訂しました（旧「交戦記録ブロック型」は破棄）

罫線で区切った記録票ブロックは**作らない**。ラウンド番号も**表に出さない**。

戦闘そのものを**報告書の文体で語らせる**（＝案D「戦闘ドラマログ型」）。

# やること（スコープ）

スライス1で生成した `events` をもとに、**戦闘を1行1アクションのドラマログとして描画する**。

対象は **隊商護衛（quest_caravan_escort）のみ**。

## 形式

- **1行 = 1アクション。動作の描写 ＋ 結果 ＋ 括弧内の数値。**
- **ラウンド番号は表に出さない**（内部保持のみ）。
- 数値は文章の中に括弧で入れる。
- 回復・アイテム消費も同じ形式で出す。
- トドメには専用の締め文を用意する。
- **戦闘内にドラマが必ず必要**。単なる数値の羅列にしない。

## 出力例（この温度感を守ること）

- 「ロウは立ちはだかり野盗からの攻撃を受け止めたが、衝撃は殺しきれなかった（ロウに-2ダメージ）」
- 「ミナは短弓から矢を放った。野盗の左肩に命中した！（野盗に-12ダメージ！）」
- 「ガッドはよろけた拍子に、野盗からの斬撃をまともに受けてしまった！（-8ダメージ！）」
- 「ロウは突撃し、野盗を弾き飛ばした！（野盗に-4ダメージ！）」
- 「エルネはガッドに応急処置を施した（ガッドは10回復）（包帯消費：1）」
- 「ミナは矢を放ち、それが最後の一撃になった。野盗を退けた。」

## 既存ログの扱い

- **既存の戦闘描写の文章ログは、このドラマログで置き換える。**（作者確認済み。既存の戦闘描写は仮置きだった）
- 戦闘以外のログ（出発・到着・結果・余韻）は**そのまま残す**。

## 挿入位置

- 戦闘フェーズの位置に入れる。**結果ログ（outcome）より前**。結果が先に漏れないこと。

## 状態語の扱い

- 状態語4段階（健在／手負い／深手／戦闘不能）は**文章に溶かして表現する**。
    - 例：「ガッドの構えが崩れた。もう長くは保たない」（＝深手への遷移）
    - 表形式の `〔ガッド：健在 → 手負い〕` のような書き方はしない。
- **状態の変化は必ず読者に伝わるようにする。** 数値はその理由の説明材料であって、心臓を掴むのは「ガッドが手負いになった」という事実のほう。

## 敵の呼称

- `data-enemies.js` の実際の名前を使う（「敵」という汎用語は使わない）。

# やらないこと（明示的に除外）

# 制約

- **エルシーはダメージ行・状態行に一切登場させない**（与ダメ・被ダメとも）
    - 撤退判断まわりの文章行には登場してよい
- **HP残量数値・HPバー・敵HP残量は表示しない**（ダメージ数値と回復量は表示する）
- **戦闘が発生しない依頼にはドラマログを出さない**（低緊張クエストへの戦闘語彙漏洩は過去のバグ。再発させない）
- 戦闘以外の既存ログは削らない
- 1依頼1関数構造を維持
- 最小差分を優先

## 実装中に決めたこと

- 敵短縮呼称は `shortName` フィールド方式（最小差分・正式名温存）。
- 回復・アイテム消費行は出さない（events に回復が無く数値が捏造になる／状態と矛盾するため。将来スライス）。
- エルシーの囮は撤退成立時のみ「撤退フレーバー行」として付与（ダメージ・状態行ルールを守る）。
- トドメ＝victory時の最後の deal イベント。「！」閾値は与ダメ≥14/被ダメ≥10（叩き台）。

## 想定と違った点・詰まった点

- 4人フル編成だと交戦行が長め（1:1方針で作者確定済み。エルネの微ダメは「戦闘に不慣れ」ニュアンスの語彙で表現）。
- 敗北（全員戦闘不能）経路はエルシー囮ビートを経ないため今回は出していない（将来の敗北演出で対応）。
