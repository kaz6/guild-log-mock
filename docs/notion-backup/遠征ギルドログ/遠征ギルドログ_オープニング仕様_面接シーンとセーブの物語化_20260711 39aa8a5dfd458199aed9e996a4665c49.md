# コンセプト

ゲーム開始直後のオープニングを、受付での「面接シーン」として演出する。プレイヤーキャラクター（＝ギルドの記録係）の自己紹介と、ゲームのセーブ機能そのものを、メタ操作ではなく物語内の行為として溶け込ませる。

# 想定フロー

1. **オープニング開始**：最初のシーンは受付での面接。
2. **プレイヤーキャラの立ち位置**：主人公＝ギルドの記録係（既存設定 `CURRENT_SPEC.md` と一致：「プレイヤーはギルドの記録係として、冒険者を依頼へ送り出し…」）。
3. **名前を尋ねられる**：プレイヤーが自分の名前を入力する。以降、ゲーム内で「プレイヤー名」として表示される。
4. **受付嬢の自己紹介**：受付嬢からも自己紹介がある。
5. **性格を尋ねられる**：面接なので性格に関する質問がある。
6. **面接は形式だけ**：どう回答しても面接は必ず通過する（建前だけの面接という設定）。
7. **面接後、最初の「仕事」＝セーブ**：メタ的な「ゲームデータのセーブ」を、ナラティブに落とし込みたい。記録係としての最初の記録行為＝セーブ、という比喩。

# 良さそうな点（レビューメモ）

- 「プレイヤー＝記録係」という主人公設定は、既存のCURRENT_[SPEC.md](http://SPEC.md)の説明文とすでに一致している。新設定ではなく明文化に近い。
- 「セーブ＝記録行為」というメタファーは、実は現行UIの語彙とすでに一致している。`app.js` には既に「記録を保存」（冒険者メモ保存ボタン）「図鑑に保存」（いきもの図鑑保存ボタン）というラベルが存在し、"保存"を物語内の行為として扱う語彙が既にゲーム内にある。今回のアイデアは、その語彙を一番最初のセーブ体験（プレイヤー自身の登録）にまで拡張するもの、と整理できる。
- 「面接はどう答えても通る」という設計は、性格診断的な質問をしつつも詰みを作らない、心理的ハードルの低いオンボーディングになる。

# 現状の実装との関係（確認事項）

- 現在、明示的な「セーブする」ボタンや演出は存在しない。`saveState()` が各操作の裏で自動的に呼ばれ、`localStorage` に保存される仕組み（マニュアルセーブ画面はない）。
- 「面接後、最初の仕事はセーブ」を成立させるには、これまで暗黙だった自動保存のどこか（おそらく一番最初の記録＝プレイヤー登録の直後）を、明示的な1回の「セーブ演出」として切り出す必要がありそう。
- プレイヤー名を保存する新しいデータ項目（例：`playerName`）が必要になる。現状の `localStorage` 保存キー `expeditionGuildLogMockV011` にどう載せるかは未検討。

# 面接で得た性格情報を後々の会話に反映する

面接で尋ねた性格情報は、保存して終わりではなく、後々の受付嬢・冒険者のセリフにちょこちょこ反映させたい。

- 入力形式は**選択式**で確定。既存の`traits`/`obsession`の`triggerTags`と同じ仕組みで、会話の発火条件にそのまま使える形を想定（自由記述は解析コストが重いため見送る）。
- 記憶するキャラは**受付嬢＋冒険者全員**で確定。全員に共有されるニュアンス（例：受付嬢が冒険者に伝えた体で「新しい記録係は注意深い人らしいよ」等）を想定。
- これはNEXT_[TASKS.md](http://TASKS.md)の既存アイデア「プレイヤーの選択を覚えていてくれるナラティブ」（過去の支給品・命名・判断などを低確率の短文ログで反映する方針）の、面接パーソナリティ版として位置づけられる。同じ方針（低確率・重い関係性イベントにはしない）を踏襲する。
