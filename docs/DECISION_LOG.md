## 2026-07-14: トドメ行は描画層で最後尾に送る（スライス3.5・時系列崩れ）

### 決定
- 戦闘ドラマログのトドメ行（決着宣言）は、**描画層（generateCaravanBattleDramaLog）でイベント位置から切り離し、全戦闘行の最後尾に置く**。エンジン（simulateBattle）は一切触らない。

### 理由・経緯
- 実機で「野盗が姿を消した後に野盗から被弾する」時系列崩れを確認。原因は、エンジンがラウンド内を同時解決（与ダメ一括→被ダメ一括）で記録し、勝敗チェックが反撃処理の後にあるため、トドメ扱いの deal（全イベント中最後の deal）の直後に同ラウンドの被弾イベントが続くこと。
- エンジン側で「敵HP0で反撃を止める」修正（案ii）は、被ダメ量が減り stage（軽/中）＝結末（護衛成功⇔護衛成功（負傷））が変わり得るため**バランス変更**になる。時系列バグの修正と混ぜない、という裁定（タスクページの「反撃を止める」指示は作者が撤回）。
- 描画層の並べ替え（案i）なら判定・数値・events は1ビットも変わらず、ドラマとしても「打ち合いの応酬の末、最後の一撃で決着」という正しい因果になる。

### 残タスク
- エンジンの「敵HP0のラウンドでも反撃が実行される」挙動そのものは**別タスク**（直すなら判定結果が変わるバランス調整として扱う）。

## 2026-07-14: ブラウザの機械翻訳を全ページで抑止（スライス3・文章崩れの真因）

### 決定
- ブラウザの機械翻訳（ページ翻訳）を全ページで抑止する。`index.html` に `<html lang="ja" translate="no">` ＋ `<meta name="google" content="notranslate">` を追加。

### 理由
- 本作は「文章そのものがゲーム体験の本体」であり、機械翻訳は表示層を書き換えて体験を破壊する。日本語→日本語の再翻訳でも語が置換され、崩れる。

### 経緯
- 実機（スマホ）で戦闘ドラマログの文章崩れが4件報告された（例：「傷を負った」→「傷を失った」、「まともに受けた」→「戦場に受けた」、「それでも棒を振るった」→「一方棒を振った」、「退くか一瞬迷ったが」→「くか一瞬だが」）。
- 読み取り専用の監査で、崩れ文字列は**現在のソースにも全コミット履歴にも一度も存在しない**ことを確認（`grep` / `git log -S`）。ドラマログの pick プールはすべて関数内インラインリテラルで共有プールは無く（語彙混線の経路なし）、ログ文を触る `.replace()`/slice も無し（結合ミスの経路なし）。実DOMで120試行・8,688行を描画しても再現ゼロ。
- 崩れは別々の生成関数2つにまたがり、単一コード経路では説明不能。機械翻訳の署名（漢字「負」を lose と誤読、接続語の言い換え、表記正規化、分かち書き解釈の崩壊）と一致。決定的裏取りとして、コード未変更のままUIラベルが「探検ギルドログ / HTMLモック / 冒険者リスト」→「遠征ギルドログ / HTML Mock / 冒険者名簿」に変化していた（ブラウザ翻訳が効いていた証拠）。

### 教訓
- **実機の表示異常を見たときは、コードを疑う前に「表示層で何かが介入していないか」を先に確認する。** ブラウザ翻訳・拡張機能・OSの読み上げ整形などは、ソースを一切変えずに表示テキストを書き換える。
- 監査タスクは「目についた文を直す」誘惑に乗らず、Audit先行（原因分類）→方針確認→修正、の順を守ったことで、存在しないバグの偽修正を回避できた。

## 2026-07-14: 戦闘シーン＝案D「戦闘ドラマログ型」へ全面改訂＋スライス2実装

### 決めたこと
- 案B「交戦記録ブロック（罫線・公文書・ラウンド番号）」は**破棄**。戦闘を報告書文体で語る**案D「戦闘ドラマログ型」**に改訂。
  - 1行=1アクション（動作描写＋結果＋括弧内の数値）。ラウンド番号は出さない。状態語4段階は文章に溶かす。
  - トドメ（victory時の最後の deal）に専用の締め文。敵は実名（地の文では短縮呼称「野盗」）。
- 対象は**隊商護衛（quest_caravan_escort）のみ**。納屋・畑は simulateBattle 未経由のため別タスク。

### 実装中に決めたこと
- **敵の短縮呼称**：`data-enemies.js` に `shortName`（enemy_road_raiders="野盗"）を追加。正式名「街道の外れに現れた徒党」は図鑑用に温存。app.js/data-quests.js の隊商関連地の文は「野盗」に統一（旧「徒党」を全置換）。
- **回復・アイテム消費行は今回出さない**：スライス1の `events` に回復が無く、数値を出すと捏造かつ状態と矛盾するため。回復はエンジンに回復処理を足す将来スライスで対応。
- **エルシーの囮**は撤退成立時のみ「撤退まわりの文章行」として出す（ダメージ・状態行には出さない、というルール内）。events に囮イベントは無いため、retreat 描画時に付与。
- **敗北（全員 downed）経路のエルシー囮ビート**は今回未対応（撤退イベントを経ないため）。将来の敗北演出スライスで扱う。
- **トドメ判定**：outcome==="victory" のとき最後の deal イベントを finisher 扱い。
- **「！」の温度**：与ダメ≥14 / 被ダメ≥10 を大ヒットの叩き台閾値に（手触りで調整可）。
- **置き換え範囲**：`generateCaravanEscortLogs` は遭遇フリ（到着〜遭遇）のみに縮小。branch別の旧戦闘プロサは削除し、`generateCaravanBattleDramaLog(events)` に差し替え。結果・余韻ログは温存。

### 実装（スライス2・完了 2026-07-14）
- 検証（Playwrightで隊商護衛40試行）：ドラマログ生成／ラウンド番号なし／括弧内数値／トドメ締め文／状態語プロサ／野盗統一（「徒党」「敵」残存なし）／旧戦闘プロサ二重なし／遭遇フリ・結果・余韻温存／エルシーがダメージ・状態行に非登場／Console赤エラー0（favicon404のみ）。

## 2026-07-14: 状態語を4段階に（健在／手負い／深手／戦闘不能）＋スライス1実装

### 決めたこと
- 交戦記録の状態語を **健在 / 手負い / 深手 / 戦闘不能** の4段階とする（案B・スライス1で確定）。
  - 閾値：個人HP 70%以下=手負い、35%以下=深手、HP0（downed）=戦闘不能。
- 当初の設計（3段階：健在/手負い/深手）から「戦闘不能」を第4語として追加。

### 理由
- 深手（まだ戦えている）と戦闘不能（倒れて動けない）はプレイヤーへの意味が全く違う。
- 同じ語にすると、4段階結末（軽傷勝利/負傷勝利/離脱/失敗）との対応が読めなくなるため分離する。

### 実装（スライス1・完了 2026-07-14）
- `simulateBattle` の戻り値に `events`（交戦イベント列）を追加。既存の判定ロジック・戻り値・表示は不変（プロパティ追加のみ）。
- イベント種別：`retreat`（撤退判断。first=round0/second=該当ラウンド）／`deal`（与ダメージ。合計を各人の攻撃寄与で按分した派生値）／`take`（被ダメージ、個人単位）／`status`（状態語の遷移時のみ）。
- エルシー（犬）は `deal`/`take`/`status` に一切登場しない（元から fighters=人間のみ、の構造を維持）。撤退判断への影響は既存のまま。
- HP残量の数値そのものはイベント列に含めない（状態語のみ）。
- 確認用に `debugBattleSim` がイベント列をconsole出力（表示＝ブロック描画はスライス2）。
- 検証：状態語境界OK／エルシー違反0（400試行）／与ダメ按分が全員に分配／深手→戦闘不能の遷移を確認（ガッド単独800試行）／実ブラウザで報告書描画・Console赤エラー0（favicon404のみ）。

## 2026-07-14: 戦闘シーンの見せ方＝案B「交戦記録ブロック型」

### 決めたこと
- 報告書ログ内に罫線区切りの「交戦記録」ブロックを埋め込む形式（専用画面なし・既存構造維持）
- 表示: 与被ダメ数値（ブロック内限定）、ラウンド番号、状態語（健在/手負い/深手）、撤退判断（文章）
- 非表示: HP残量数値・HPバー・敵HP残量・命中率
- 旧方針改訂:「被ダメは数値非表示」→「交戦記録ブロック内に限り表示可、HPは状態語」
- エルシー: ダメージ行に登場しない（与被とも）。撤退判断の文章行には登場可
- 報告書一覧に「交戦記録 添付あり」バッジ（中身は開封まで不明）

### 理由
- ハラハラの主軸は開封の瞬間（MPO的）。数値は事後検証の道具と役割分担
- 「ギルド規定の交戦記録票」という世界内の理屈で記録係トーンを維持
- 確定済みの内部設計（前衛60%配分・撤退2回制・離脱適性）が数字で読み返せる形で回収される

### 却下案
- 案A（与ダメのみ数値）: 温度不足、片側数値では検証不能
- 案C（フルRPG窓）: 「読む」体験が「見る」に変質、実装過重
